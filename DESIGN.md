# DESIGN.md — Architecture & Core Contracts

## Mission
`rag-eval` is a framework-agnostic CLI and library to score any RAG pipeline on:
1. **Retrieval quality**: Did the retriever fetch the right chunks? (Precision@k)
2. **Answer faithfulness**: Does the generated answer strictly rely on the retrieved context? (Claim extraction & verification)

Works with Haystack, LangChain, LlamaIndex, or vanilla Python pipelines using plain JSONL inputs with no framework lock-in.

---

## Core Data Contract

### Input JSONL
Each line of the input file represents one evaluation sample formatted as a JSON object:

```json
{
  "question": "What is the capital of France?",
  "answer": "Paris is the capital of France.",
  "context": [
    "Paris is the capital and most populous city of France."
  ],
  "golden_documents": [
    "Paris is the capital and most populous city of France."
  ],
  "retrieved": [
    "Paris is the capital and most populous city of France.",
    "Lyon is a major city in France."
  ],
  "id": "sample-001"
}
```

### Schema Rules
- **Required fields**:
  - `question` (`str`): The query submitted to the RAG pipeline.
  - `answer` (`str`): The response generated by the generator/LLM.
  - `context` (`list[str]`): Chunks passed to the LLM as context (minimum 1 chunk).
- **Optional fields**:
  - `golden_documents` (`list[str] | None`): Ground-truth chunks required for retrieval scoring.
  - `retrieved` (`list[str] | None`): Chunks returned by retriever in rank order.
  - `id` (`str`): Unique sample identifier (auto-generates UUID4 if omitted).

---

## Evaluation Metrics

### 1. Retrieval Precision@k
Calculated when `retrieved` and `golden_documents` are provided:
$$\text{Precision@k} = \frac{|\text{set}(\text{retrieved}[:k]) \cap \text{set}(\text{golden\_documents})|}{k}$$
Duplicates in `golden_documents` do not artificially inflate the score (set semantics).

### 2. Answer Faithfulness (Claim Overlap)
Zero-API-key heuristic evaluator:
1. **Claim Extraction**: Answer is segmented into atomic claims on sentence delimiters (`[.!?]`) and coordinating conjunctions (`, but `, `; `, etc.).
2. **Tokenization & Stopword Filtering**: Content tokens matching `[a-z0-9]+` are extracted after removing common English stopwords.
3. **Context Verification**: A claim is supported if $\ge 80\%$ (`SUPPORT_THRESHOLD = 0.8`) of its content words are present in the context chunks.
4. **Faithfulness Score**:
$$\text{Faithfulness} = \frac{|\text{supported claims}|}{|\text{total claims}|}$$
If an answer contains no claims, faithfulness defaults to `1.0`.

### 3. Optional LLM Judge
Pluggable via `Judge` protocol:
- Prompts an LLM (`gpt-4o-mini` or custom model) with: *"Answer strictly yes or no: is the claim supported by the context?"*
- Calculates faithfulness across verified claims.
